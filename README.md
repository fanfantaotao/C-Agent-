# mushsci × Coze 主工作区融合原型

前端原型项目（Vite 6 + React 19）。既可作为本地服务器启动开发，也可导出为单文件 HTML 分发。

## 拿到这个压缩包后怎么跑起来

前置：装 **Node.js 18+**（https://nodejs.org）。首次启动需要联网装依赖（约 80 MB）。

```text
Windows ：双击 start-wb.cmd          （自动装依赖 + 起服务 + 打开浏览器）
手动     ：npm ci   然后  npm run dev:bridge
mac/Linux：npm ci && npm run dev:bridge
```

打开 **http://127.0.0.1:5180/** 即可。这一条命令比 `npm run dev` 多了一层「AI 点选改源码」能力。

### AI 点选改源码（wb-bridge）

页面上点元素 → 把「改什么」写清楚 → 一次性提交给 AI，AI 直接改 `src/` 并热更新。

1. 页面右下角点 **⌖ 选择元素**（或 `Ctrl+Shift+E`）
2. 连续点多个元素累积成清单（重复点同一元素 = 移除），`Esc` 结束并打开清单
3. 逐项写要求，或用底部的「统一要求」批量描述，点 **全部发送**
4. 让**打开着这个项目的 AI agent** 处理队列 —— 它读 `.wb-bridge/session.json`（或 `/__wb__/api/requests`），改 `src/Workspace.jsx` 等源码，改完标 done，页面自动刷新

要点：

- 桥只在 `npm run dev:bridge` / `npm run dev`（即 `vite` 开发模式）下生效；`npm run build` 产出的单文件**不含**选择器，是干净的分发件。
- 点选**不依赖特定浏览器**：Chrome / Edge 都行，桥是开发服务器上的队列，浏览器只是"输入设备"。
- **改代码那一步必须由 AI agent 完成** —— 页面自己不会改源码。没有 agent 时只能收集清单，改不动。
- 每个元素都带 `data-wb-src="src/Workspace.jsx:246:131"`（编译期注入），点选因此能精确落到源码某一行。
- 细节与接口清单见 `AGENTS.md`。


## 本地启动

```bash
npm install
npm run dev
```

默认地址 `http://localhost:5173/`。

> `vite.config.mjs` 里 `server.host` 是 `0.0.0.0`（局域网可访问）。只想本机访问就把它改成 `"127.0.0.1"`。

| 命令 | 说明 |
| --- | --- |
| `npm run dev` | 启动开发服务器，带热更新 |
| `npm run dev:bridge` | 同上，但固定 `127.0.0.1:5180`，并启用 AI 点选桥 |
| `npm run build` | 构建到 `dist/client` |
| `npm run preview` | 预览构建产物 |
| `python scripts/export-single-file.py` | 把 `dist/client` 打包成单文件 HTML |

导出脚本会同时写两份：项目内的 `standalone.html`，以及**上级目录**的 `mushsci-Coze主工作区融合原型.html`（对外交付的单文件）。所以改完源码后执行 `npm run build` + 导出脚本，单文件即可与项目保持一致。

```

src/
  main.jsx             入口，挂载 App
  App.jsx              再导出 Workspace
  Workspace.jsx        主组件：首页 / 工作区 / 消息 / 模型选择器等
  workspace.css        工作区样式
  reference.css        参考设计样式（左侧栏、输入框、弹层基础样式）
  messages.json        示例对话数据
  reference.json       图片资源引用（mascot / avatar / model）
public/assets/         品牌图片（svg + jpg）
scripts/               单文件导出、参考设计导入
worker/                站点 worker
tests/                 worker 测试
```

## 原型说明

首页沿用 `UI给的产品内设计参考.html`，点击右上角“查看协作示例”进入多智能体工作区。可滚动浏览、展开处理过程与工具详情、引用消息、添加表情、复制表格、提及 Agent、选择技能和知识库、搜索定位、查看成果摘录、发送并停止模拟回复。

左侧保留参考外观，右侧栏不在此次范围。页面为本地前端原型，未连接真实模型、知识库或云盘。消息及对话名保存在当前浏览器本地；点击“查看协作示例”可恢复示例。

执行过程采用连续叙事流：已用时、阶段回应、逐条具体动作、子智能体/Worker 头像与任务摘要。点击摘要在右侧查看该智能体的执行记录，临时 Worker 仅在详情标注“临时创建”，结束后保留入口与过程。当前 MVP 不做语义聚合；同次调用结束更新原记录，失败、重试分别保留，停止先等待确认。当前需求与接入边界见 `MVP_EXECUTION_RULES.md`；旧接入文档的冲突规则已标为历史草案。

## 多智能体交互（规则体现在行为里，不体现在文案里）

| 场景 | 行为 |
| --- | --- |
| 默认主控 | MushSCI 为协调者，输入区智能体选择器常显当前主控 |
| 未 @ | 主控拆分任务 → 子智能体认领 → 创建临时智能体辅助 → 主控统一反馈 |
| 主动 @ | 指定智能体直接反馈 |
| 画像智能体 | 画像标签自动创建、长期存在；可在「画像智能体管理」改方向 |
| 临时智能体 | 任务内创建，结束后保留头像入口与右侧执行记录；不可 @，不进常驻助手列表 |
| 会话 @ 范围 | 进入会话时锁定；范围外或临时的 @ 会被拒绝并提示 |
| 执行中改方向 | 不即时生效，进入排队，当前任务完成后自动应用 |
| 创建范围 | 仅支持基于画像标签创建画像智能体 |
| 删除引用 | 删除后的引用不可再次引用，文件列表对应项置灰 |

> 主界面**不出现**规则说明文案（无「本期不支持 / 待补充」这类句子、无角色徽标墙、无教程横幅）。规则原文清单只在「任务设置 → 多智能体交互规则」里，供验收对照。

## 模型选择器

输入框右下角的模型按钮点击后弹出浮层（浅色，与整体风格一致）：

- 顶部两个 tab：`语言模型` / `多模态模型`，各自独立列表
- 分组标题「内置模型」，每行显示：品牌图标 + 模型名 (+ 钻石标) + 消耗速度；当前选中项显示绿色对勾
- 右侧详情卡跟随悬停行出现，展示：一句话定位、消耗速度、可用功能标签；按可用空间自动左右翻边
- 选中某项后回填输入框右侧按钮文字并自动收起浮层

实现位置：`ModelPicker` / `BrandIcon` / `Gem` 组件与 `MODEL_LANG`、`MODEL_MULTI` 数据在 `src/Workspace.jsx`；样式在 `src/workspace.css` 的「模型选择器」段落。品牌色图标块（`.mp-ic.*`）是品牌标识，不随主题变。

新增模型只需往 `MODEL_LANG` 或 `MODEL_MULTI` 里追加一条：`{n:名称, b:品牌, sp:消耗速度, sig:信号档位(g|y|o), gem:是否钻石, d:一句话, load:负载文案, tag:功能标签}`。
